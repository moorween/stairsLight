# Stairs Light

Автономный контроллер лестницы: двухъядерный ESP32, PlatformIO, Arduino-ESP32,
subjectLab, ArduinoHA, Gyver Settings. Wi-Fi и Home Assistant не нужны для работы
датчиков и анимации.

## Подключение и конфигурация

| Устройство | GPIO |
|---|---|
| Нижний PIR | 26 |
| Верхний PIR | 25 |
| WS2812 DATA | 23 |

Все аппаратные параметры находятся в `include/HardwareConfig.h`:

- 15 ступеней, снизу вверх: `19,19,19,19,18,19,25,19,18,18,18,18,18,18,18`.
- 283 рабочих LED, плюс один жертвенный перед первой ступенью: всего 284.
- Жертвенный LED всегда чёрный и не участвует ни в одном эффекте или тесте.
- Первая ступень подключена справа налево, следующая слева направо.
- Порядок байтов GRB; для другой ленты изменить `wireChannels`.
- PIR активны высоким уровнем, входы с внутренней подтяжкой вниз.
- Стабилизация PIR при старте — 30 секунд (`pirWarmupMs`). В это время сырые
  входы видны в диагностике, автоматические срабатывания подавляются.

Нумерация ступеней начинается снизу. Логическая позиция на каждой ступени
отсчитывается слева направо, независимо от её физического подключения.

Настройки рассчитаны на обычный двухъядерный ESP32 с flash 4 MB,
например NodeMCU-32S / ESP32-WROOM. Для другой платы поменять `board` и проверить GPIO.
Питание ленты отдельное, GND ленты, ESP32 и датчиков общий.
Выход PIR, подключённый к GPIO, должен иметь уровень, допустимый для ESP32.

## Сборка и первая загрузка

Зависимости закреплены в `platformio.ini`: pioarduino 55.03.34 / Arduino 3.3.4,
subjectLab v1.1.0, ArduinoHA 2.1.0, Settings 1.3.13 и совместимые версии зависимостей.
Вывод WS2812 реализован встроенным RMT Arduino-ESP32; FastLED не требуется.

1. Скопировать `include/Secrets.example.h` в `include/Secrets.h` и задать пароли.
   `Secrets.h` исключён из git. Если файла нет, применяются значения из примера.
2. Подключить ESP32 по USB и выполнить:

```sh
pio run -e esp32-usb
pio run -e esp32-usb -t upload
pio device monitor -b 115200
```

При необходимости явно указать порт: `pio run -e esp32-usb -t upload --upload-port /dev/cu.…`.

Разметка `partitions.csv` содержит два слота приложения по 1 900 544 байта.
Первая установка этой разметки выполняется по USB. Обычное OTA обновляет только
приложение: изменить разметку или размер flash через него нельзя.

## Первоначальная настройка

При отсутствии сохранённой сети ESP32 открывает защищённую точку доступа
`StairsLight-XXXXXX`.

Пароли из примера (если `Secrets.h` не создан):

| Доступ | Пароль |
|---|---|
| Wi-Fi точки доступа | `stairs-setup` |
| Web UI | `stairs-admin` |
| OTA | `stairs-update` |

1. Подключиться к точке доступа и открыть `http://192.168.4.1`.
2. Войти с паролем web UI. Gyver Settings показывает кнопку входа в своём меню.
3. В группе Wi-Fi нажать «Поиск сетей», выбрать SSID или ввести его вручную.
4. Ввести пароль и нажать «Проверить и сохранить Wi-Fi».

Новые реквизиты сохраняются после успешного подключения, получения IP и двух
секунд стабильного соединения. Проверка занимает до 20 секунд. При ошибке
контроллер возвращается к прежней сети. Во время проверки точка доступа остаётся
доступной. SSID и пароль сохраняются одним NVS-блоком, чтобы при отключении питания
они не превратились в пару из разных настроек.

Пустой пароль Wi-Fi означает «использовать прежний» только для прежнего SSID.
Для сети без пароля включить «Открытая сеть». Для нового защищённого SSID пароль
обязателен. Поиск сетей не сохраняет выбранный SSID без кнопки подключения.

При следующих запусках контроллер подключается автоматически. После 60 секунд
без Wi-Fi открывает резервную точку доступа и продолжает попытки подключения.
Открытая для настройки точка доступа остаётся включённой до перезагрузки.

В домашней сети интерфейс доступен по показанному IP и `http://stairslight.local`
(если клиент поддерживает mDNS). Имя `.local` настраивается в web UI.

## MQTT и Home Assistant

В группе MQTT указать адрес брокера, порт, пользователя и пароль. Проверить
подключение отдельной кнопкой, включить MQTT и сохранить. Тест не сохраняет
реквизиты и не создаёт сущности. MQTT в первой версии работает без TLS.

Пустой новый пароль MQTT сохраняет прежний. Для удаления пароля есть отдельный
переключатель. Для Home Assistant должна быть включена интеграция MQTT с тем же
брокером и префиксом Discovery (по умолчанию `homeassistant`).

Устройство создаёт шесть сущностей с идентификатором устройства на основе MAC:

| Сущность | Назначение |
|---|---|
| Background | Включение, яркость и RGB-цвет фона |
| Motion lighting enabled | Разрешение автоматики, яркость и RGB-цвет движения |
| Bottom motion | Обработанный нижний PIR |
| Top motion | Обработанный верхний PIR |
| Animation active | Фактическое выполнение анимации движения |
| Background effect | Выбор Solid или одного из пяти эффектов |

Состояние `Motion lighting enabled` означает разрешённую автоматику, а не наличие
человека или фактически горящий свет. Дополнительный выключатель с тем же смыслом
не создаётся. PIR продолжают публиковаться, когда автоматика выключена.

Изменения цвета, яркости, разрешений и эффекта синхронизируются между HA и web UI.
После восстановления MQTT контроллер повторно публикует текущее состояние.
Смена префикса Discovery может потребовать удаления прежних сущностей в HA
и старых retained discovery-сообщений брокера.

## Анимация и фон

| Первый PIR | Разгорание | Второй PIR сработал | Второй не сработал |
|---|---|---|---|
| Нижний | 1 → 15 | Гашение 1 → 15 | Гашение 15 → 1 |
| Верхний | 15 → 1 | Гашение 15 → 1 | Гашение 1 → 15 |

Противоположный PIR выбирает направление гашения и продлевает таймаут; немедленного
гашения не происходит. Направление текущего прохода сохраняется до гашения.
Если оба датчика зарегистрированы в одном цикле опроса, все ступени разгораются
одновременно и затем так же гаснут.

Каждая ступень разгорается целиком с плавной кривой smoothstep. Интервал ступеней,
длительность разгорания и гашения настраиваются отдельно. Переходы перекрываются:
время полного прохода = `14 × интервал + длительность перехода`.

Таймаут — время до начала гашения после последней активности. Пока обработанный
PIR активен, таймаут продлевается. Гашение не начинается до окончания разгорания.
Повторное движение во время гашения начинает новое разгорание в направлении входа,
с текущей яркости каждой ступени, без её скачка или предварительного выключения.
При выключении автоматики текущая анимация плавно гаснет.

Два PIR не позволяют точно считать людей и отличать выход от встречного входа.
Контроллер использует последовательность срабатываний и продление освещения.

Фон и движение независимы. Движение плавно замещает фон на каждой ступени;
после гашения возвращается актуальный фоновый кадр. Эффекты фона:
Solid, Breathing, Wave, Comet, Twinkle, Rainbow. Радуга задаёт собственные цвета,
остальные используют выбранный цвет. Скорость и интенсивность не влияют на Solid.

## PIR: программная фильтрация

У каждого датчика свои настройки:

- подтверждение HIGH: вход должен оставаться активным заданное число миллисекунд;
- подтверждение LOW: защита от коротких провалов сигнала;
- пауза повторного события: подавление повторных фронтов;
- инверсия логического уровня входа.

Пауза повторного события не скрывает активный уровень и не разрешает гашение при
активном PIR. Физические HIGH/LOW и обработанные состояния видны отдельно.
Это фильтры сигнала, а не регулировка дальности или аналоговой чувствительности PIR.

## OTA из PlatformIO

Контроллер должен быть доступен с компьютера по сети. Простой способ:

```sh
python3 tools/upload_ota.py 192.168.1.50
```

Скрипт запросит текущий пароль OTA без сохранения в файле и запустит PlatformIO.
Также можно использовать имя `stairslight.local` либо прямую команду:

```sh
export STAIRS_OTA_HOST=stairslight.local
read -s 'STAIRS_OTA_PASSWORD?OTA password: '
export STAIRS_OTA_PASSWORD
pio run -e esp32-ota -t upload
unset STAIRS_OTA_PASSWORD
```

Пример `read -s` выше — для zsh в macOS. В других оболочках используйте Python-скрипт.
Если PlatformIO не находится в PATH, скрипт ищет `~/.platformio/penv/bin/pio`;
можно явно передать `--pio /путь/к/pio`.

При начале OTA настройки света сохраняются, лестница переводится в постоянный
тёплый свет. После этого повторная передача LED-кадров приостанавливается до
завершения/ошибки обновления. При успехе ESP32 перезагружается, при ошибке обычная
работа восстанавливается. Прогресс виден в Serial. После перезагрузки PIR снова
проходят период стабилизации; настройки сохраняются в NVS.

Изменить пароли AP/web/OTA можно в разделе «Доступ и OTA». Пустые поля оставляют
пароли прежними. Применение перезагружает контроллер. Изменение `Secrets.h` само
по себе не заменяет уже сохранённые в NVS пароли.

## Диагностика и проверка

Web UI показывает входы PIR, фазу и направление анимации, таймаут, готовность RMT,
ошибки вывода, потери межзадачных очередей, память, подключения Wi-Fi и MQTT.

Кнопки имитации PIR запускают обычную логику движения, но не подделывают состояние
физических датчиков в HA. При отключённой автоматике имитация не запускает движение.
«Проверить ступени» подсвечивает каждую ступень на одну секунду. Через 15 секунд
контроллер возвращается к обычному кадру; тест можно остановить кнопкой.

Настройки света применяются сразу и сохраняются после двух секунд без изменений.
Есть принудительное сохранение, перезагрузка и подтверждаемый сброс только сети
либо всех настроек. Полный сброс возвращает пароли из прошивки.

Тесты алгоритма на компьютере (нужен C++17-компилятор):

```sh
sh tools/test.sh
```

Проверяются геометрия и змейка, четыре сценария направления, повторное движение,
активный PIR, включение/выключение автоматики, одновременные события, нулевые времена,
долгое разгорание, переполнение `millis()`, фильтры PIR и ограничение настроек.
Тесты запускаются с AddressSanitizer и UndefinedBehaviorSanitizer.

На плате проверить последовательно: чёрный жертвенный LED; соответствие ступеней;
цвета RGB; оба направления с вторым PIR и без него; движение при гашении; работу
без Wi-Fi/MQTT; сохранение после перезагрузки; загрузку по OTA.
Реальное оборудование и OTA-передача не проверяются тестами на компьютере.

## Устройство кода

| Файл | Ответственность |
|---|---|
| `HardwareConfig.h` | GPIO, геометрия, порядок цветов, период стабилизации |
| `LightSettings.h` | Настройки и допустимые диапазоны |
| `PirFilter.h` | Подтверждение уровней и подавление повторов |
| `MotionEngine.h` | Алгоритм и плавные коэффициенты ступеней, без Arduino |
| `LedRenderer.h` | Эффекты, смешивание, физическое отображение, RMT |
| `Events.h` | subjectLab: команды и поток состояния между задачами |
| `Storage.h` | Версионированное сохранение NVS |
| `NetworkUi.cpp` | Подключение Wi-Fi, настройка, web UI, OTA |
| `HaBridge.cpp` | ArduinoHA и синхронизация сущностей |
| `main.cpp` | Задача света на ядре 1 и сетевого интерфейса на ядре 0 |

Сетевые объекты принадлежат только сетевой задаче. LED-буфер, PIR и алгоритм —
только задаче света. Изменения передаются через `Action`, диагностические снимки —
через `BehaviorSubject` и `Delivery::Latest`. Отказ постановки команды в очередь
показывается как ошибка и не сохраняется как успешное изменение.

Пины и геометрию меняют в прошивке; остальные пользовательские настройки — в web UI.
При изменении сохраняемых структур необходимо поднять версию схемы хранения
и при необходимости реализовать миграцию.
